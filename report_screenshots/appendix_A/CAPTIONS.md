# Appendix A — Screenshots and Test Scenarios (captions)

All figures below were produced from the real system: the trained YOLO11n model, the MediaPipe
hand landmarker, and the Pygame simulator driven over the real UDP link. Dataset photos are from
the HaGRID test split (CC BY-SA 4.0), which was held out from training.

## A.1 YOLO11 Static Gesture Recognition

- **A1_1_yolo_predictions_per_gesture_class.jpg**
  YOLO11n predictions on held-out test images, one per class, with confidence and the command
  each class triggers in the final system. *Proves:* all 9 static gestures are recognised with
  high confidence (0.97–0.99) on unseen people and backgrounds.
- **A1_2_confusion_matrix_test_set.png**
  Normalised confusion matrix on the test split (1,079 images, 9 classes). *Proves:* very few
  classes get confused with each other; overall precision 0.989, recall 0.975.
- **A1_3_precision_recall_curve_test_set.png**
  Precision–recall curves per class on the test split. *Proves:* mAP@0.5 = 0.992 and
  mAP@0.5:0.95 = 0.990.
- **A1_4_test_batch_predictions.jpg**
  A batch of test images with predicted boxes and labels, generated by the evaluation.
- **A1_5_training_curves.png**
  Training/validation loss, precision/recall and mAP over 41 epochs (from `results.csv`).
  *Shows:* validation mAP levels off near 0.99 from about epoch 25, and the validation loss
  falls and stays level instead of rising, so there is no sign of strong overfitting.

Per-class test results (P / R / mAP50): fist 1.000 / 0.983 / 0.995 · palm 1.000 / 0.992 / 0.995 ·
like 0.951 / 0.962 / 0.990 · dislike 0.979 / 0.992 / 0.991 · peace 0.997 / 1.000 / 0.995 ·
ok 1.000 / 0.987 / 0.995 · call 0.983 / 0.924 / 0.982 · stop 1.000 / 0.987 / 0.995 ·
no_gesture 0.992 / 0.950 / 0.992. Inference: 4.4 ms/image (RTX 4050 Laptop GPU).

- **A2_1_mediapipe_21_landmarks_and_finger_states.jpg**
  The 21 MediaPipe hand landmarks (fingertips in red), the thumb vector used for steering

## A.4 End-to-End Gesture-to-Vehicle Integration

*(live — press P in the camera window; each press saves a matched camera + simulator pair
with the same timestamp in `report_screenshots/`)*

- Driving: thumbs-up, tilted to steer while the hand is raised for throttle.
- Gear: peace sign → camera panel shows GEAR R, simulator shows SELECT: R and the car reverses.
- Horn: call sign → HORN ON in both windows.
- Emergency stop: open palm → PANIC STOP in both windows, the car brakes to 0 km/h.

## A.5 UDP Communication and Simulator Test Scenarios

- **A5_1_udp_connected_30hz.png** — Connection status: "GESTURE CONNECTED [~30 Hz]", packet
  count, packet age and the YOLO gesture label received. *Proves:* the controller streams at
  camera rate with packet ages of a few tens of milliseconds.
- **A5_2_malformed_packets_rejected.png** — Nine malformed packets (non-JSON, broken JSON,
  invalid UTF-8) were sent. They are counted (Malformed: 9) and dropped while the car keeps driving
  normally. *Proves:* bad input can't crash or hijack the simulator.
- **A5_3_panic_stop_engaged.png** — Panic-stop packet received at speed. The banner shows and
  gear P is engaged while the car brakes hard, even though the throttle is still at 100%.
- **A5_4_panic_stop_vehicle_halted.png** — One second later: 0 km/h. *Proves:* the emergency
  stop overrides the throttle.
- **A5_5_udp_timeout_keyboard_fallback.png** — The sender stopped. After the 0.5 s timeout the
  status changes to "WAITING FOR UDP (KEYBOARD READY)" and the inputs return to idle. *Proves:*
  losing the gesture link fails safe.
- **A5_6_minimal_packet_backward_compatible.png** — A packet with only the original three
  fields (steering, throttle, brake) is still accepted and drives the car (defaults: gear D, no
  horn).
- **A5_7_simulator_unit_tests.png** — The simulator's automated test suite (14 tests: throttle,
  braking, reverse, steering limit, heading change, panic stop, off-road friction, UDP packet
  parsing, malformed-packet handling, track/city generation, camera and HUD rendering), all
  passing.
